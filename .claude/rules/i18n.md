# Languages in the app: hy, ru, en (rule 14)

## In code
- User-facing strings (UI, verdicts, advice, report, CLI) go through `i18n.t("group.name", **params)`.
- Add a key to `locales/hy.py` first, then to `ru.py` and `en.py` (the `translator` subagent), with the
  same `{placeholders}`. Exception: the move cards WL-21 … WL-26 add `hy` only; WL-27 / WL-28 translate.
- Lookup: current language → `en` → the key itself.
- The old inline Armenian strings move to keys in WL-21 … WL-26. Don't add new inline ones.
- Key names: `check.<check key>.title` / `.hint`, `check.<check key>.<what>` for check results,
  `check.probe_failed` shared by server-list probes, `error.<what>` for `short_error()` words.
- Static UI text: `t(key)`, read where it is shown. `CheckSpec.title` / `.hint` are properties that
  return a fresh `Msg` on every read, so `CheckResult.title` keeps its key.
- Text that outlives the moment it is made (results built in the worker thread): `Msg(key, **params)`, a
  `str` that keeps its key and params. `i18n.render(text)` shows it in the current language; nested `Msg`
  params are rendered again too. Never build such text with `+` or an f-string around a `Msg`: the result
  is a plain `str` and loses its key. Put the pieces in params instead.
- `str(exc)` flattens a `Msg`: pass `HttpFailure.message`, not `exc`, into a `Msg`.
- No key for text without words (`host → 1.2.3.4 (4 ms)`); `fmt_ms()` stays "ms" in every language.
- `t()` has no plural forms: in ru/en, word counts so they read right for any number (`серверов: {count}`).
- The default language is `hy` until WL-30 reads the OS locale.
- `set_language()` raises `ValueError` for an unknown code.
- Planned (I18N epic): switch the language in the window and remember the choice.

## Tone and terms
- Informal and direct: hy `դու`, ru `ты`, en "you".
- Keep gamer and network terms as the Armenian UI does: ping, packet loss, jitter, relay, router and
  provider in Latin script.
- The full style guide is in `.claude/agents/translator.md`.
